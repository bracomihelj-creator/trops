## 2. What happens AFTER filling dates

End-to-end flow:

```
Python fetch_edavki_mrn()
  → starts localhost HTTP server on random port (/mrn)
  → opens Chrome: DDV_Deklaracija.aspx?kirkpr_edavki_mrn=http://127.0.0.1:PORT/mrn&kirkpr_tax=…&kirkpr_firm=…&kirkpr_from=…&kirkpr_to=…

content_automation.js (on DDV_Deklaracija page load)
  → chrome.runtime.sendMessage({ action: "kirkprFetchEdavkiMrn", … })

background.js → fetchEdavkiMrnAndReport()
  1. ensureEdavkiMrnForTaxpayer()
     - Find/create eDavki tab (background, active:false)
     - If wrong taxpayer → navigate to DeputyList.aspx, search & click taxpayer
     - Navigate to DDV_Deklaracija.aspx if not already there
     - Wait for tab complete (up to ~16s polling)

  2. fillEdavkiMrnDatesAndSearch(dateFrom, dateTo)   ← injected into page
     - Fill #OpenMainContent_MainContent_txtFromDate / txtToDate
     - CLICK #OpenMainContent_MainContent_btnSearch (or form.submit fallback)

  3. WAIT for ASP.NET postback
     - delay(1800ms)
     - waitTabComplete(tab, 30 attempts × 400ms)
     - delay(600ms)

  4. extractEdavkiMrnGrid()   ← injected into page
     - Scrape table #OpenMainContent_MainContent_gridDeclaration
     - Parse MRN rows, dedupe (P-Popravek over O-Original)
     - Sum DDV amounts

  5. POST JSON result to localhost (postKonto62Report → fetch POST)

  6. Close trigger tab if URL contains kirkpr_edavki_mrn=
     - chrome.tabs.remove(sender.tab.id)
     - Keep window unfocused
```

**No extra pages** beyond DeputyList (taxpayer switch) and DDV_Deklaracija. No external API calls — only DOM scrape + localhost POST.

## 4. How to STOP after filling dates (no search / scrape / wait)

There is **no existing flag** like `kirkpr_fill_only`. Today, date fill always leads to search + scrape + POST.

### Option A — Minimal JS change (recommended)

In `fillEdavkiMrnDatesAndSearch()` (lines 1643–1654), **remove the search click**:

```javascript
// After setVal(from) and setVal(to):
return { ok: true, searched: false, from: from.value, to: to.value };
// DELETE: btn.click() and form.submit()
```

In `fetchEdavkiMrnAndReport()` (lines 1805–1839), **return early after fill**:

```javascript
if (dateFrom || dateTo) {
  const filled = await chrome.scripting.executeScript({ … fillEdavkiMrnDatesAndSearch … });
  // STOP HERE — do not delay, scrape, or POST
  return { ok: true, message: "Datumi vneseni, brez iskanja." };
}
```

### Option B — Add URL param gate (cleaner long-term)

1. Python adds `kirkpr_fill_only=1` to the query string.
2. `content_automation.js` passes it in the message.
3. `fetchEdavkiMrnAndReport()` checks it and skips search/scrape/POST when set.

### Option C — Python-only (no extension change)

Use `open_edavki_mrn_declarations()` from `edavki_links.py` — opens `DDV_Deklaracija.aspx` **without** `kirkpr_edavki_mrn`, so the extension never triggers automation. Dates must be filled manually.

**Do not** call `fetch_edavki_mrn()` if you only want the page opened with dates — it always waits for the POST callback and will timeout after 45–50s.

### Option D — Disable trigger entirely

Omit `kirkpr_edavki_mrn` from the URL. The content script block at lines 16–29 exits immediately when that param is missing.
